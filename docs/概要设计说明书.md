## 1. 设计决策

下列决定是需求没有指定、但概要设计必须先定下来的规则。评审时若要改，直接改编号。

| 编号 | 决定 |
| --- | --- |
| DD-01 | 使用 C++20、Qt 6 长期支持版和 Qt Widgets。只做 Windows 桌面，不使用 QML |
| DD-02 | 发布为 Windows 64 位目录，并用 windeployqt 带上 Qt 运行库，用户不必单独安装 Qt。程序目录保持多文件，不做成单文件 |
| DD-03 | 通过进程调用随包的 `ffmpeg.exe` 和 `ffprobe.exe`，不链接 FFmpeg 的库 |
| DD-04 | 视频编码优先使用显卡。H.264 和 H.265 的尝试顺序是 NVIDIA NVENC、Intel QSV、AMD AMF，最后是 CPU。VP9 先试 Intel QSV，再使用 CPU。界面仍然只选择 H.264、H.265 或 VP9。同一次任务只用一种实现；显卡步骤失败时，该任务改用 CPU 再试一次 |
| DD-05 | 编码速度固定为均衡档，界面不提供这项选择。具体参数由编码器实现决定，见详细设计 |
| DD-06 | 安装包使用 Inno Setup。绿色版是同一套发布目录的压缩包。安装向导只保留目录页，确认后其余步骤自动完成，以落实 FR-P-04 |
| DD-16 | 使用 Qt 的系统托盘。主窗口关闭按钮只隐藏窗口；进程退出只通过托盘「退出」，以落实 FR-U-05 至 FR-U-08 |
| DD-07 | 媒体信息探测和正式处理共用一把执行锁，同一时刻最多一个 FFmpeg 或 FFprobe 进程 |
| DD-08 | 需求里点名的失败原因，能在启动处理前判定的，就在启动前判定。处理过程失败且无法归类时，才使用「处理失败，请检查文件是否损坏」 |
| DD-09 | FFmpeg 的原始输出只留在该次进程的内存中，用来归类；进程结束后丢弃，不写日志文件，不显示到界面 |
| DD-10 | 合并在需要重新编码时，先把每一段写到系统临时目录，再拼接成最终文件。成功、失败和取消都会删除临时目录 |
| DD-11 | 界面、剪贴板和 `_info.txt` 共用同一个信息文本格式化器，保证三处文字一致 |
| DD-12 | 只处理每条视频里的第一条视频流。压缩和裁剪保留全部音轨并重新编码。只换容器时复制全部流，任一流不被目标容器接受则整项失败 |
| DD-13 | 除媒体信息的展示外，第一版不保证章节、封面进入输出文件 |
| DD-14 | 裁剪不提供码率输入，始终使用需求中的默认质量。源视频没有音轨时，裁剪仍输出无音轨视频 |
| DD-15 | C++ 命名空间使用英文 `MediaTool`。窗口、安装项和关于页显示「媒体小工具」 |

## 2. 总体结构

程序分成四层。上层可以调用下层，下层不调用上层。界面不拼 FFmpeg 参数，基础设施不决定中文文案。

```
界面层 MediaTool.App
    主窗口、托盘图标、功能参数、进度、结果清单、关于页
        |
应用层 MediaTool.Application
    任务编排、取消策略、文件夹循环、合并的整体成败
        |
领域层 MediaTool.Domain
    媒体模型、命名、时间、配套文件、容器是否可复制、中文说明、执行计划
        |
基础设施层 MediaTool.Infrastructure
    FFprobe、FFmpeg 进程、临时目录、输出文件删除、许可证文件路径
```

对应目录是 `src/app`、`src/application`、`src/domain`、`src/infrastructure`。界面层使用 Qt Widgets，进程调用放在基础设施层，使用 Qt Core。

一次处理的数据沿这个方向流动：

1. 界面把用户选择收成 `JobRequest`。
2. 应用层解析出待处理的输入清单，并按规则决定这项失败后是继续还是整单停止。
3. 领域层根据探测结果生成 `ExecutionPlan`。计划只描述要运行的步骤和要产生的文件。
4. 基础设施层按计划启动进程，汇报进度，并在失败或取消时删除未完成文件。
5. 应用层收成 `ItemResult` 清单，界面只展示这份清单。

## 3. 发布目录

安装版和绿色版使用同一套相对布局。程序通过自身所在目录定位随包文件，不读取系统 PATH，以落实 NFR-04。

```
MediaTool.exe
MediaTool.dll 及其他自包含运行文件
ffmpeg/ffmpeg.exe
ffmpeg/ffprobe.exe
licenses/LICENSE.txt
licenses/FFMPEG-LICENSE.txt
licenses/SOURCE.txt
```

`licenses/LICENSE.txt` 是本工具的 GPL 文本。`FFMPEG-LICENSE.txt` 是随包 FFmpeg 的许可证文本。`SOURCE.txt` 写明源代码在发布物中的位置，或获取源代码的地址，以落实 FR-P-03。关于页打开这些文件，并显示程序版本和 `ffprobe -version` 的首行版本，以落实 FR-P-02。

卸载只删除安装目录和开始菜单快捷方式，不扫描、不删除用户视频目录，以落实 FR-P-01 和 AC-16。

## 4. 模块

### 4.1 界面层

| 模块 | 职责 | 主要需求 |
| --- | --- | --- |
| MainWindow | 选择输入、切换功能、开始与取消、展示进度和清单；关闭按钮只隐藏窗口 | FR-U-01、FR-U-07、FR-C-06、FR-C-07 |
| TrayIcon | 托盘图标、右键菜单、双击显示主界面、退出进程 | FR-U-05、FR-U-06、FR-U-08 |
| ParameterPanel | 按功能显示参数，并执行输入格式检查 | FR-U-04、FR-A-01、FR-T-01、FR-V-01 |
| MediaInfoPanel | 单个视频的信息、复制、导出 | FR-I-01、FR-I-02、FR-I-03 |
| ResultList | 四种结果和复制全文 | FR-C-08 |
| AboutWindow | 版本号和许可证入口 | FR-P-02、FR-P-03 |

选中单个视频时，媒体信息区始终显示，不要求当前功能正好是「媒体信息」。这样用户在提取音轨或字幕前能看到从 1 开始的序号。文件夹模式下不逐个铺开信息全文。

参数区随功能切换：

| 功能 | 参数区 |
| --- | --- |
| 媒体信息 | 导出。单个文件还可复制 |
| 提取音频 | 音轨、格式、音量 |
| 提取字幕 | 字幕轨、格式 |
| 封装字幕 | 单个视频时选择外挂字幕；文件夹时只说明将查找同名配套 |
| 裁剪 | 「开始和结束」或「开始和时长」，以及两个时间文本 |
| 合并 | 容器、码率；多个视频时可调整顺序 |
| 换容器或压缩 | 操作种类、容器；压缩时再显示分辨率、编码器和码率 |
| 音轨 | 去掉、保留或替换；保留时选序号；替换单个视频时选外部音频；音量用于保留和替换 |

单个视频的音轨和字幕序号用下拉框，选项来自刚探测到的实际序号。文件夹模式没有统一的探测结果，序号用数字输入，默认 1，执行时逐个检查。

「只换容器」时，分辨率、码率和编码器不可用。容器选成 WebM 且操作是压缩时，编码器固定显示 VP9，不能改成 H.264 或 H.265。这些联动在界面层完成，应用层仍按同一规则拒绝非法组合。

第一版没有设置文件。通过托盘「退出」结束进程后再打开，全部回到需求第 5 节的默认值，以落实 FR-C-12。仅隐藏主界面后再显示时，界面状态保持不变。

### 4.2 应用层

`TaskRunner` 是唯一的执行入口。

- 状态只有空闲和运行中。运行中时开始按钮不可用，以落实 FR-C-06。
- 媒体信息的自动探测也走这把锁，以落实 DD-07。用户改选文件时，取消尚未完成的探测，再探测新文件。正式处理进行时不启动新的探测。
- 文件夹任务按输入清单逐个执行。一项失败只记录并继续，以落实 FR-C-08。
- 合并不进入这个逐项继续的循环，单独走整体流程，以落实 FR-G-05。

取消由界面询问后，把选择交回 `TaskRunner`：

| 场景 | 行为 |
| --- | --- |
| 只有一个输入 | 不再询问，停止当前进程，删除未完成输出 |
| 文件夹任务，用户选择停掉整个任务 | 停止当前进程，删除未完成输出，剩余项记为未处理 |
| 文件夹任务，用户选择只跳过当前文件 | 停止当前进程，删除未完成输出，该项记为已取消，然后继续 |
| 用户关闭询问 | 任务继续 |
| 合并 | 不再询问，停止并删除临时文件和未完成输出 |

应用层不解析 FFmpeg 文本。它只处理领域层返回的已归类结果。

### 4.3 领域层

| 模块 | 职责 |
| --- | --- |
| MediaModel | 时长、分辨率、帧率、编码、码率、音轨、字幕、章节 |
| InfoText | 把 MediaModel 格式化成唯一的中文文本 |
| TimeRange | 解析时间，并换算成开始和结束 |
| OutputNames | 功能后缀、冲突时的 ` (2)` 序号、自然排序 |
| SidecarMatch | 按优先级查找同名字幕或音频 |
| ContainerFit | 判断全部流能否直接复制进目标容器 |
| ScaleRule | 计算压缩高度：目标更小时才缩小，宽高取偶数 |
| Messages | 需求点名的中文说明，集中在一处 |
| Planners | 每个功能一个计划器，输入探测结果和参数，输出执行计划或一项已归类失败 |

功能后缀与需求 FR-C-04 的表一致，集中在 `OutputNames`，界面不拼文件名。

自然排序用于文件夹合并：把文件名切成数字段和非数字段。数字段按整数比较，非数字段按不区分大小写的顺序比较。因此 `clip2` 排在 `clip10` 前面。

配套文件的优先级与需求一致。字幕是 `.srt`、`.ass`、`.vtt`。外部音频是 `.m4a`、`.mp3`、`.wav`、`.flac`。比较时忽略扩展名大小写，主文件名必须与视频主文件名一致。

容器直接复制的判定：

| 目标 | 允许的视频 | 允许的音频 | 允许的字幕 |
| --- | --- | --- | --- |
| MP4 | h264、hevc | aac、mp3、ac3、eac3 | 无字幕，或 mov_text |
| MKV | 探测得到的任意编码 | 任意 | 任意 |
| WebM | vp8、vp9、av1 | vorbis、opus | 无字幕，或 webvtt |

存在上表之外的流时，只换容器失败，说明「目标容器无法直接容纳现有编码」。计划器不改成压缩计划。

字幕种类判定：

| 种类 | 编码 |
| --- | --- |
| 文本 | subrip、ass、ssa、webvtt、mov_text、text |
| 图像 | hdmv_pgs_subtitle、dvd_subtitle、dvb_subtitle、xsub |

未列入的字幕编码按图像处理，避免被误导出成空的文本字幕。

音量 100 表示计划中不加入音量变化。其他整数按「输入值 / 100」传给处理步骤。0 仍然生成音轨，只是音量为零。去掉音轨是另一条计划，输出里不映射任何音轨。

### 4.4 基础设施层

| 模块 | 职责 |
| --- | --- |
| BundleLayout | 定位随包 FFmpeg、FFprobe 和许可证 |
| ProbeClient | 运行 FFprobe，读 JSON，填 MediaModel |
| ProcessClient | 运行 FFmpeg，汇报进度，响应取消 |
| OutputCleaner | 删除未完成输出和临时目录；删不掉时把路径交给结果说明 |
| InfoFileWriter | 按 UTF-8（无 BOM）写出 `_info.txt` |

`ProcessClient` 使用参数数组启动进程，不经过 `cmd.exe`。取消时结束该进程及其子进程，再等待它退出。进度优先读取 FFmpeg 的 progress 输出，用已输出时长除以探测到的总时长得到百分比。总时长无效时，界面显示「进行中」，不显示百分比。

临时目录位于系统临时目录下的 `MediaTool` 子目录，一次任务一个子文件夹。最终成片仍写到源文件所在文件夹。

## 5. 主流程

### 5.1 选中单个视频

1. 文件对话框只允许 `.mp4`、`.mkv`、`.avi`、`.mov`、`.webm`。
2. 取得执行锁后运行 FFprobe。
3. 成功则刷新媒体信息区。失败则显示「无法读取这个文件」，并清空可选择的音轨和字幕序号。
4. 这个探测不产生输出文件，也不进入结果清单。

### 5.2 文件夹任务

1. 列出该文件夹直接包含的符合扩展名的视频，不进入子文件夹。
2. 一个都没有时不启动任务，说明「这个文件夹里没有可处理的视频」。
3. 对每个视频：探测、生成计划、执行、记录一项结果。
4. 计划阶段已经失败的，不启动 FFmpeg，该项记为失败。
5. 执行失败或被跳过时删除该视频对应的未完成输出，然后按取消选择决定继续或停止。
6. 结束后展示清单。成功行包含输出路径。

媒体信息的文件夹入口只写 txt，规则与上面相同。界面不展示每份 txt 的正文。

### 5.3 合并

1. 多个视频沿用用户排列的顺序。文件夹入口先做自然排序。
2. 少于两个视频时不启动，说明「至少需要两个视频」。
3. 先逐个探测。任何一个无法读取，整次失败，说明里包含该文件名，不产生成片。
4. 全部可读后，用第一条的分辨率、帧率和全部流的编码判断能否直接拼接，并检查目标容器能否容纳。
5. 能直接拼接时，一次 FFmpeg 完成，中间不写临时视频。
6. 不能直接拼接时，按 DD-10 先把每一段按第一段的宽高和帧率写到临时目录，再拼成最终文件。MP4 和 MKV 的临时段使用 H.264 与 AAC。WebM 使用 VP9 与 Opus。较小画面在这一步允许放大。
7. 任一步失败或取消，删除临时目录和未完成的最终文件。已成功写出的最终文件只在整次成功后保留。

### 5.4 替换音轨的时长

计划以视频时长为准。外部音频较短时补静音到视频结束，较长时截断到视频结束。视频流复制。新音频在 WebM 中使用 Opus，在其他保留的容器中使用 AAC。AVI 放不下 AAC 时，输出改为同名规则下的 MP4，成功说明包含「已改用 MP4」。

## 6. 各功能的计划

计划器只产生下面这些结果之一：一项中文失败，或一组按顺序执行的步骤。详细参数表在详细设计中按本节展开。

| 功能 | 计划要点 | 需求 |
| --- | --- | --- |
| 媒体信息 | 不调用 FFmpeg。文本来自 InfoText，写出 UTF-8 文件 | FR-I-03 |
| 提取音频 | 映射所选音轨，按格式重新编码。MP3 192 kbps，AAC 192 kbps，WAV 为 16 位 PCM，FLAC 无损。采样率和声道跟随该音轨 | FR-A-04 |
| 提取字幕 | 文本按 SRT、ASS、VTT 导出为 UTF-8。原样时把该字幕流复制进只含这一流的 MKV。图像字幕遇到文本格式则失败 | FR-S-03、FR-S-04 |
| 封装字幕 | 视频流和全部音轨复制，字幕作为软字幕放进 MKV。视频和音频不重新编码 | FR-M-01、FR-M-02 |
| 裁剪 | 按开始和结束重新编码。WebM 源为 VP9 与 Opus，其他源为 H.264 与 AAC，质量为默认质量。输出容器与源相同 | FR-T-03、FR-T-04 |
| 只换容器 | 通过 ContainerFit 才生成复制全部流的计划，否则直接失败 | FR-V-02、FR-V-04 |
| 压缩 | 第一条视频流按分辨率规则和所选编码器重新编码，全部音轨重新编码。编码器实现按 DD-04。MP4、MKV 的音频为 AAC 160 kbps。WebM 为 Opus 128 kbps。码率留空时，H.264、H.265 的质量目标相当于 CRF 23，VP9 相当于 CRF 32 | FR-V-03、FR-V-05、FR-V-06、FR-V-07 |
| 去掉音轨 | 只复制第一条视频流，不映射音轨。源没有音轨则失败 | FR-R-01 |
| 保留音轨 | 复制第一条视频流和所选音轨。音量为 100 且容器能容纳该音轨时复制音频，否则重新编码 | FR-R-02 |
| 替换音轨 | 复制第一条视频流，用外部音频按 5.4 生成唯一音轨，并应用音量 | FR-R-03、FR-R-04 |

输出文件名一律先经过 `OutputNames`。目标已存在时向后取 ` (2)`、` (3)`，不覆盖已有文件。

## 7. 错误与取消

中文说明集中在 `Messages`。下表是需求点名原因与判定位置。

| 说明 | 判定位置 |
| --- | --- |
| 找不到随包的 FFmpeg | 启动程序后检查随包文件；处理前再检查一次 |
| 这个文件夹里没有可处理的视频 | 列举输入之前 |
| 至少需要两个视频 | 合并开始前 |
| 没有音轨 | 计划器对照探测结果 |
| 没有字幕 | 计划器对照探测结果 |
| 这一轨是图像字幕，请选原样 | 计划器对照字幕种类 |
| 找不到同名字幕 / 找不到同名音频 | SidecarMatch |
| 字幕文件无法读取 | 计划器在封装前检查外挂字幕能否打开 |
| 时间无效 | TimeRange，在启动任务前检查；界面同时禁止开始 |
| 结束时间超过视频时长 | 计划器把结束时间与该视频时长比较 |
| 目标容器无法直接容纳现有编码 | ContainerFit |
| 无法写入 | 创建输出文件失败时 |
| 无法读取这个文件 | FFprobe 失败，或正式处理前探测失败 |
| 已取消 | 用户取消并已停止进程 |
| 处理失败，请检查文件是否损坏 | 进程非零退出，且不属于上表 |

成功、失败、已取消、未处理是结果清单仅有的四种状态。成功说明可以追加事实，例如实际使用的配套文件名，或「已改用 MP4」。

删除未完成输出失败时，不把该项改成成功。原有失败或取消说明保留，并追加残留文件的完整路径。

## 8. 界面状态

主窗口在空闲和运行中的可用操作：

| 操作 | 空闲 | 运行中 |
| --- | --- | --- |
| 选择输入、修改参数、切换功能 | 可用 | 不可用 |
| 开始 | 输入合法时可用 | 不可用 |
| 取消 | 不可用 | 可用 |
| 复制信息、复制清单 | 有内容时可用 | 信息保持原样；清单在结束后可复制 |
| 关于 | 可用 | 可用 |
| 移动和关闭窗口 | 可用 | 可用。关闭窗口只隐藏主界面，任务继续；托盘「退出」才停掉整个任务并结束进程 |
| 托盘显示主界面 / 双击托盘 | 可用 | 可用 |
| 托盘退出 | 可用 | 可用。先按停掉整个任务处理，再退出 |

处理过程中界面线程不等待进程退出。进度文本包含当前文件名；文件夹任务还包含「第几个 / 共几个」。
