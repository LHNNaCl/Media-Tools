## 1. 详细设计补充

下面这些规则用来填上概要设计里仍然空着的实现细节。

| 编号 | 规则 |
| --- | --- |
| LD-01 | 封面流（`attached_pic`）、`attachment` 和 `data` 不参与容器判断，也不复制到输出 |
| LD-02 | 帧率在模型里保留分子和分母。显示时再换算。需要重编码时，把原始分数传给 FFmpeg |
| LD-03 | 裁剪把 `-ss` 和 `-t` 放在 `-i` 之后，换准确时间，不换快进 |
| LD-04 | 进度只解析 progress 输出里的 `out_time`。不使用 `out_time_ms` |
| LD-05 | 合并重编码时，只要有一段带音轨，所有临时段都变成立体声、48000 Hz。没有音轨的那段用静音补齐。所有段都没有音轨时，输出也不加音轨 |
| LD-06 | 合并的基准宽高是第一段宽高各向下取偶数。其他段拉伸到这个宽高 |
| LD-07 | 压缩或裁剪时，宽或高为奇数且不需要缩放到 1080p 或 720p，就缩到不大于原尺寸的偶数 |
| LD-08 | 视频码率只接受 1 到 200000 的整数，单位 kbps。留空表示默认质量 |
| LD-09 | 结束时间大于探测时长加 0.001 秒，才算超过视频时长 |
| LD-10 | 视频编码的速度和质量参数按第 6.1 节，随显卡或 CPU 实现变化。质量目标仍是 H.264、H.265 相当于 CRF 23，VP9 相当于 CRF 32 |
| LD-11 | H.265 写入 MP4 或 MOV 时追加 `-tag:v hvc1`，与显卡或 CPU 实现无关 |
| LD-12 | 语言标签缺失，或者值为 `und`，界面都显示「未标记」 |
| LD-13 | 版本号只写在根目录 `CMakeLists.txt` 的 `project(VERSION)`。安装脚本从发布命令接收同一个版本号 |
| LD-14 | 安装包按当前用户安装，不要求管理员。安装向导只保留目录选择页，确认后自动完成其余步骤，不展示欢迎页、许可证页、准备安装页和完成页 |
| LD-17 | 主窗口拦截关闭事件：只调用 `hide()`，不退出。托盘菜单「退出」在空闲时直接 `QApplication::quit()`；运行中则先按停掉整个任务处理，清理完成或最多再等 10 秒后退出 |
| LD-15 | 标准错误最多在内存中保留 64 KB，进程结束后丢弃 |
| LD-16 | 一次任务开始时记下当时的编码器实现。显卡步骤失败且不是取消时，删掉未完成输出，改用该编码族的 CPU 实现重跑整个当前项。合并则整次重跑。每个任务最多回退一次 |

## 2. 工程结构

```
CMakeLists.txt
src/domain/
src/application/
src/infrastructure/
src/app/
tests/domain/
tests/application/
third_party/ffmpeg/
third_party/licenses/
installer/MediaTool.iss
tools/publish.ps1
tools/make-samples.ps1
```

使用 CMake 和 MSVC 编译。`domain` 与 `application` 不链接 Qt。`infrastructure` 使用 Qt Core 的 `QProcess`。`app` 使用 Qt Widgets。领域测试只链接 `domain`。应用测试链接 `application`，并用假的探测和进程对象。测试框架使用 GoogleTest。

根目录版本号：

```cmake
project(MediaTool VERSION 1.0.0 LANGUAGES CXX)
```

关于页的程序版本使用这个 `1.0.0`。

发布由 `tools/publish.ps1` 完成：

```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
cmake --install build --prefix publish --config Release
windeployqt --release --no-translations publish/MediaTool.exe
```

脚本接着把 `third_party/ffmpeg/ffmpeg.exe`、`ffprobe.exe` 复制到 `publish/ffmpeg/`，把许可证复制到 `publish/licenses/`。CMake、windeployqt 或任一随包文件失败时，脚本停止，不生成安装包。FFmpeg 不在本机编译，使用预先放入 `third_party/ffmpeg/` 的 GPL 构建。该构建必须带有 `libx264`、`libx265`、`libvpx-vp9`、`h264_nvenc`、`hevc_nvenc`、`h264_qsv`、`hevc_qsv`、`vp9_qsv`、`h264_amf`、`hevc_amf`。某个显卡编码器名字不存在时，探测直接跳过它，不把整个构建判为失败。三个 CPU 编码器缺一，则按「找不到随包的 FFmpeg」处理。

## 3. 类型

轨道序号在模型和界面里都从 1 开始。拼 FFmpeg 参数时减 1。

```cpp
enum class Feature { Info, ExtractAudio, ExtractSubtitle, MuxSubtitle, Trim, Merge, Convert, Audio };
enum class ItemStatus { Succeeded, Failed, Canceled, NotProcessed };
enum class AudioFormat { Mp3, M4a, Wav, Flac };
enum class SubtitleFormat { Srt, Ass, Vtt, Raw };
enum class ContainerKind { Mp4, Mkv, Webm };
enum class ConvertMode { Remux, Compress };
enum class ResolutionPreset { Original, P1080, P720 };
enum class VideoEncoder { H264, H265, Vp9 };
enum class EncoderImpl { Nvenc, Qsv, Amf, Cpu };
enum class AudioEditMode { Remove, Keep, Replace };
enum class TrimMode { StartEnd, StartDuration };
enum class SubtitleKind { Text, Image };
enum class StepKind { Ffmpeg, WriteText };

struct AudioTrack {
    int number;
    std::string codec;
    int channels;
    std::optional<int> sampleRate;
    std::optional<std::string> languageTag;
};

struct SubtitleTrack {
    int number;
    std::string codec;
    std::optional<std::string> languageTag;
    SubtitleKind kind;
};

struct ChapterMark {
    double startSeconds;
    std::optional<std::string> title;
};

struct MediaInfo {
    std::string path;
    std::optional<double> durationSeconds;
    int width;
    int height;
    std::optional<int> frameNumerator;
    std::optional<int> frameDenominator;
    std::string videoCodec;
    std::optional<long long> videoBitrateBits;
    std::optional<std::string> pixelFormat;
    std::vector<AudioTrack> audios;
    std::vector<SubtitleTrack> subtitles;
    std::vector<ChapterMark> chapters;
};

struct ProcessStep {
    StepKind kind;
    std::vector<std::string> arguments;
    std::string outputPath;
    std::optional<std::string> textContent;
};

struct ExecutionPlan {
    std::vector<ProcessStep> steps;
    std::string successMessage;
};

struct PlanResult {
    std::optional<ExecutionPlan> plan;
    std::optional<std::string> failureMessage;
};
```

`arguments` 不含可执行文件名。`WriteText` 的 `textContent` 就是要写入的 UTF-8 正文，`arguments` 为空。

计划器签名：

```cpp
PlanResult plan(...);
```

计划器不访问磁盘上的视频内容。配套文件是否存在、输出路径是否可写，由应用层在调用计划器之前查好，再把结果传进去。这样领域测试不必准备真实视频。

## 4. 探测与信息文本

### 4.1 FFprobe 参数

```
-hide_banner -loglevel error -print_format json -show_format -show_streams -show_chapters -i {input}
```

标准输出按 JSON 解析。退出码不为 0、JSON 无效、或找不到可作主画面的视频流时，结果为「无法读取这个文件」。

### 4.2 字段映射

| MediaInfo | JSON |
| --- | --- |
| DurationSeconds | `format.duration`。缺失或不是数字时为 null |
| Width、Height | 主视频流的 `width`、`height` |
| FrameNumerator、FrameDenominator | 主视频流的 `avg_frame_rate`，格式为 `分子/分母`。分母为 0 或字段缺失时，两个值都为 null |
| VideoCodec | 主视频流的 `codec_name` |
| VideoBitrateBits | 主视频流的 `bit_rate`。缺失或不是正数时为 null |
| PixelFormat | 主视频流的 `pix_fmt` |
| Audios | `codec_type == audio` 的流，按出现顺序编号 |
| Subtitles | `codec_type == subtitle` 的流，按出现顺序编号 |
| Chapters | `chapters[]` 的 `start_time` 和 `tags.title` |

主视频流是第一条同时满足这些条件的视频流：`codec_type == video`，且 `disposition.attached_pic` 不为 1。

音轨：

| AudioTrack | JSON |
| --- | --- |
| Number | 该类型中的序号，从 1 开始 |
| Codec | `codec_name` |
| Channels | `channels`。缺失时按 0 |
| SampleRate | `sample_rate`。缺失时为 null |
| LanguageTag | `tags.language`。没有该字段时为 null |

字幕的 Codec、LanguageTag 同样取自 `codec_name` 和 `tags.language`。种类按概要设计第 4.3 节的编码表判断，表外编码一律是图像。

### 4.3 信息文本

`InfoText.Format(MediaInfo)` 是界面、剪贴板和 `_info.txt` 的唯一来源。编码为 UTF-8，无 BOM。正文以换行结束，行尾是 `\n`。

时长和章节时间：

```
总毫秒 = round(秒 × 1000)
时 = 总毫秒 / 3600000
分 = (总毫秒 / 60000) % 60
秒 = (总毫秒 / 1000) % 60
毫秒 = 总毫秒 % 1000
文本 = 时（至少两位）:分两位:秒两位.毫秒三位
```

时长缺失时写「未知」。帧率缺失时写「未知」。能整除时写整数，否则保留三位小数。码率按 `round(比特每秒 / 1000)` 写成 `{n} kbps`，没有正数码率时写「未知」。

固定段落：

```
时长：00:01:30.000
分辨率：1920×1080
帧率：24
视频编码：h264
视频码率：2500 kbps
音轨：
1. aac，2 声道，未标记
字幕：
1. subrip，chi，文本
章节：
00:00:10.000 开场
```

没有音轨时，音轨段只有一行「无音轨」。没有字幕时，字幕段只有一行「无字幕」。没有章节时，章节段只有一行「无章节」。章节没有标题时，该行只有时间。语言按 LD-12 显示。字幕种类只写「文本」或「图像」。

## 5. 领域算法

### 5.1 时间

先去掉首尾空白。空字符串无效。

| 形式 | 含义 |
| --- | --- |
| `秒` | 0 秒及以上的整数 |
| `分:秒` | 分大于或等于 0，秒为 0 到 59 |
| `时:分:秒` | 时大于或等于 0，分和秒都为 0 到 59 |

不要求补零。`1:2:3` 等于 1 小时 2 分 3 秒。`1:60`、负数、小数和空字符串都无效。

开始时间必须大于或等于 0。结束时间必须大于开始时间。时长必须大于 0。「开始加时长」先换成结束时间，再做同一组检查。与视频时长比较时使用 LD-09。

传给 FFmpeg 的秒数使用不变文化，固定三位小数，例如 `10.000`。

### 5.2 输出文件名

后缀与需求 FR-C-04 一致。扩展名使用小写。

| 功能 | 后缀 | 扩展名 |
| --- | --- | --- |
| 媒体信息 | `_info` | `.txt` |
| 提取音频 | `_audio` | `.mp3`、`.m4a`、`.wav`、`.flac` |
| 提取字幕 | `_subtitle` | `.srt`、`.ass`、`.vtt`、`.mkv` |
| 封装字幕 | `_muxed` | `.mkv` |
| 裁剪 | `_trim` | 与源扩展名相同 |
| 合并 | `_merge` | 用户所选容器 |
| 只换容器 | `_remux` | 用户所选容器 |
| 压缩 | `_compress` | 用户所选容器 |
| 去掉音轨 | `_silent` | 最终容器 |
| 保留音轨 | `_audiotrack` | 最终容器 |
| 替换音轨 | `_replaced` | 最终容器 |

分配顺序：

1. `{主名}{后缀}{扩展名}`
2. 已存在时改用 `{主名}{后缀} (2){扩展名}`
3. 序号继续增加，直到得到一个不存在的路径

多个视频合并时，主名是第一个视频的主名，目录是它的所在目录。文件夹合并时，主名是文件夹名，目录是该文件夹。其他功能的主名是源视频主名，目录是源视频所在目录。

清理器只允许删除本次计划列出的输出，以及本次任务的临时目录。路径与任一输入相同的文件拒绝删除。

### 5.3 自然排序

把文件名切成数字段和非数字段。数字段按整数值比较，不用字符串长度。数值相同再比较下一组。全部分组都相同后，先按不区分大小写的完整文件名比较，再按原始文件名比较，保证顺序稳定。

`clip2` 因此排在 `clip10` 前面。

### 5.4 配套文件

在视频所在目录查找。主名必须相同，扩展名按概要设计的优先级，并忽略大小写。命中多个不同扩展名时只取优先级最高的一个。成功说明追加「已使用 {文件名}」。

字幕优先级：`.srt`、`.ass`、`.vtt`。音频优先级：`.m4a`、`.mp3`、`.wav`、`.flac`。

### 5.5 容器判断

先去掉 LD-01 排除的流，再使用概要设计的容器表。MKV 接受剩余的任意编码。任一剩余流不在目标表内，就返回失败，说明「目标容器无法直接容纳现有编码」。

### 5.6 压缩高度

| 条件 | 滤镜 |
| --- | --- |
| 原分辨率，宽高都是偶数 | 不缩放 |
| 原分辨率，宽或高为奇数 | `scale=trunc(iw/2)*2:trunc(ih/2)*2` |
| 1080p，源高度大于 1080 | `scale=-2:1080` |
| 720p，源高度大于 720 | `scale=-2:720` |
| 1080p 或 720p，源高度小于或等于目标 | 按「原分辨率」那一行处理 |

### 5.7 音量

100 不写滤镜。其他值写成 `volume={输入/100}`，不变文化，两位小数。0 写成 `volume=0.00`，仍然保留音轨。

### 5.8 新音频的容器

重新编码音频时：

| 源容器 | 音频编码器 | 输出容器 | 说明 |
| --- | --- | --- | --- |
| webm | libopus，128 kbps | webm | 无额外说明 |
| avi | aac，160 kbps | mp4 | 成功说明追加「已改用 MP4」 |
| 其他 | aac，160 kbps | 保持源容器 | 无额外说明 |

音量为 100，且该音轨编码已被目标容器接受时，保留音轨改为复制，不走上表。

## 6. 进程约定

FFmpeg 与 FFprobe 由 `QProcess` 启动，不经过 `cmd.exe`，并隐藏窗口。标准输出和标准错误都重定向。进程放入 Windows Job Object，对象带 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`。取消时结束这个 Job，从而结束进程树，再等待最多 5 秒。

处理步骤的公共前缀：

```
-hide_banner -loglevel error -progress pipe:1 -nostats
```

进度行只认 `out_time=时:分:秒.微秒`。百分比为已输出秒数除以探测时长，限制在 0 到 100。探测时长无效时界面写「进行中」。

退出码为 0 且预期输出已生成，才算步骤成功。用户取消导致的非零退出记为已取消。显卡编码器的其他非零退出先按 LD-16 回退。回退用尽或本次用的就是 CPU 时，才记为「处理失败，请检查文件是否损坏」。

临时目录是 `%TEMP%\MediaTool\{32位任务号}\`。

MP4、M4A、MOV 的重新编码或复制输出追加：

```
-movflags +faststart
```

所有重新编码的视频追加 `-pix_fmt yuv420p`。

### 6.1 视频编码器

启动后、接受用户任务前，持有执行锁，串行探测编码器。界面在此期间显示「正在检测视频编码器…」。先运行：

```
-hide_banner -loglevel error -encoders
```

H.264、H.265、VP9 三族分别探测。某一族按下面的顺序取第一个可用实现，之后的实现不再探测。CPU 实现不单独做编码试验；它在 `-encoders` 里必须存在。

| 编码族 | 尝试顺序 |
| --- | --- |
| H.264 | `h264_nvenc`、`h264_qsv`、`h264_amf`、`libx264` |
| H.265 | `hevc_nvenc`、`hevc_qsv`、`hevc_amf`、`libx265` |
| VP9 | `vp9_qsv`、`libvpx-vp9` |

显卡候选先要出现在 `-encoders` 输出里。然后用与正式编码相同的像素格式做一帧试验，退出码为 0 才算可用。单次试验最长 8 秒：

```
-hide_banner -loglevel error -f lavfi -i color=c=black:s=256x256:r=30:d=0.1 -frames:v 1 -an -c:v {编码器} {该实现的速度参数} -pix_fmt yuv420p -f null -
```

探测结果保存在本次进程中。关于页用「NVIDIA NVENC」「Intel QSV」「AMD AMF」「CPU」显示三族的结果。

正式编码的参数如下。码率留空时使用质量列，填写时使用码率列，两列不同时出现。H.265 写入 MP4 或 MOV 时再追加 `-tag:v hvc1`。

| 实现 | 速度 | 码率留空 | 填写码率 |
| --- | --- | --- | --- |
| NVENC，H.264 / H.265 | `-preset p5` | `-rc vbr -cq 23 -b:v 0` | `-rc vbr -b:v {码率}k` |
| QSV，H.264 / H.265 | `-preset medium` | `-global_quality 23` | `-b:v {码率}k` |
| QSV，VP9 | `-preset medium` | `-global_quality 32` | `-b:v {码率}k` |
| AMF，H.264 / H.265 | `-quality balanced` | `-rc cqp -qp_i 23 -qp_p 23` | `-rc cbr -b:v {码率}k` |
| CPU，H.264 / H.265 | `-preset medium` | `-crf 23` | `-b:v {码率}k` |
| CPU，VP9 | `-deadline good -cpu-used 2` | `-crf 32 -b:v 0` | `-b:v {码率}k` |

计划器只接收已经选定的 `EncoderImpl`，不自己探测显卡。这样编码器参数可以不启动 FFmpeg 做测试。

一次任务开始时复制当时的三族选择。该任务中途即使探测结果不会变，也不改用另一种显卡。按 LD-16 回退时，只把这一任务换成 CPU，不影响下一次任务继续优先使用显卡。

## 7. 功能参数

下列参数接在第 6 节的公共前缀之后。`{index}` 已是从 0 开始的流序号。`{gain}` 只在音量不是 100 时插入。

### 7.1 媒体信息

不启动 FFmpeg。步骤种类是 `WriteText`，正文来自第 4.3 节。单个视频使用界面上已经探测好的模型，保证和屏幕一致。文件夹任务对每个文件重新探测后再格式化。

### 7.2 提取音频

没有所选音轨时失败，说明「没有音轨」。

公共映射：

```
-i {input} -map 0:a:{index} -vn
```

| 格式 | 接着写入的参数 | 输出扩展名 |
| --- | --- | --- |
| MP3 | `-filter:a {gain} -c:a libmp3lame -b:a 192k` | `.mp3` |
| M4A | `-filter:a {gain} -c:a aac -b:a 192k`，以及 faststart | `.m4a` |
| WAV | `-filter:a {gain} -c:a pcm_s16le` | `.wav` |
| FLAC | `-filter:a {gain} -c:a flac` | `.flac` |

不写 `-ar` 和 `-ac`，让所选音轨的采样率和声道保持不变。音量为 100 时不写 `-filter:a`。

### 7.3 提取字幕

没有所选字幕时失败，说明「没有字幕」。图像字幕搭配 SRT、ASS 或 VTT 时失败，说明「这一轨是图像字幕，请选原样」。

| 格式 | 参数 | 扩展名 |
| --- | --- | --- |
| SRT | `-i {input} -map 0:s:{index} -c:s srt` | `.srt` |
| ASS | `-i {input} -map 0:s:{index} -c:s ass` | `.ass` |
| VTT | `-i {input} -map 0:s:{index} -c:s webvtt` | `.vtt` |
| 原样 | `-i {input} -map 0:s:{index} -c:s copy` | `.mkv` |

### 7.4 封装字幕

单个视频由用户选定外挂文件。文件夹使用配套查找。文件打不开或长度为 0 时失败，说明「字幕文件无法读取」。找不到配套文件时失败，说明「找不到同名字幕」。

扩展名对应的字幕编码器：`.srt` 为 `srt`，`.ass` 为 `ass`，`.vtt` 为 `webvtt`。

```
-i {video} -i {subtitle} -map 0:v:0 -map 0:a? -map 1:0 -c:v copy -c:a copy -c:s {字幕编码器} {output}.mkv
```

视频和音频不重新编码。

### 7.5 裁剪

时间无效时不启动任务。结束时间超过该视频时长时，该项失败，说明「结束时间超过视频时长」。时长缺失时，该项失败，说明「无法读取这个文件」。没有音轨仍然继续，并改用 `-an`，不写音频编码器。

```
-i {input} -ss {start} -t {duration} -map 0:v:0 -map 0:a?
```

| 源 | 视频 | 音频 |
| --- | --- | --- |
| webm | 第 6.1 节的 VP9 参数，码率留空 | `-c:a libopus -b:a 128k` |
| 其他 | 第 6.1 节的 H.264 参数，码率留空 | `-c:a aac -b:a 160k` |

有音轨时使用 `-map 0:a?` 和上表的音频参数。没有音轨时改为 `-an`。缩放按第 5.6 节的「原分辨率」行。输出扩展名与源相同。

### 7.6 只换容器

`ContainerFit` 失败时不生成步骤。成功时按探测结果逐条映射保留下来的流：

```
-i {input} -map 0:{绝对序号} ... -c copy {output}
```

不写分辨率、码率和编码器。

### 7.7 压缩

WebM 搭配 H.264 或 H.265 时，应用层在计划前拒绝，说明「WebM 只能使用 VP9」。

```
-i {input} -map 0:v:0 -map 0:a? -vf {缩放} {第 6.1 节的视频参数} -pix_fmt yuv420p -c:a {音频}
```

没有音轨时去掉 `-map 0:a?` 和音频参数，改为 `-an`。不需要缩放时不写 `-vf`。视频参数按用户选择的 H.264、H.265 或 VP9，以及本任务记下的实现，从第 6.1 节取值。

| 容器 | 视频 | 音频 |
| --- | --- | --- |
| MP4、MKV | 用户选择的 H.264 或 H.265。MP4 上的 H.265 追加 `-tag:v hvc1` | `-c:a aac -b:a 160k` |
| WebM | 固定 VP9 | `-c:a libopus -b:a 128k` |

### 7.8 音轨

没有音轨时，「去掉」和「保留」失败，说明「没有音轨」。「替换」允许源视频没有音轨。

去掉：

```
-i {input} -map 0:v:0 -c:v copy -an {output}
```

保留，且可以复制音频：

```
-i {input} -map 0:v:0 -map 0:a:{index} -c:v copy -c:a copy {output}
```

保留，但需要重新编码：

```
-i {input} -map 0:v:0 -map 0:a:{index} -c:v copy -filter:a {gain} -c:a {第5.8节的编码器} {output}
```

音量为 100 时，重新编码的命令不写 `-filter:a`。输出容器按第 5.8 节决定。

替换时，外部音频扩展名只接受 `.mp3`、`.m4a`、`.wav`、`.flac`。文件夹找不到配套文件时，说明「找不到同名音频」。视频时长缺失时，说明「无法读取这个文件」。

滤镜顺序固定为先截断、再补静音：

```
atrim=end={视频时长},apad=whole_dur={视频时长}
```

音量不是 100 时，把 `volume={gain},` 放在这组滤镜最前面。

```
-i {video} -i {audio} -map 0:v:0 -map 1:a:0 -c:v copy -filter:a {滤镜} -c:a {第5.8节的编码器} {output}
```

## 8. 合并

少于两个视频时不启动，说明「至少需要两个视频」。先逐个探测。任何一个探测失败，整次失败，说明使用「无法读取这个文件：{文件名}」，不启动 FFmpeg，不留下成片。

### 8.1 能否直接拼接

全部输入都满足下面的条件才直接拼接：

- 主视频的编码、偶数化之前的宽高、帧率分数、像素格式相同
- 音轨数量相同，并且按顺序比较编码、采样率和声道数都相同
- 字幕数量相同，并且按顺序比较编码相同
- 这些保留流能放进用户选择的目标容器

直接拼接时，在临时目录写 `list.txt`，每行是 `file '{路径}'`。路径里的单引号写成 `'\''`。然后只跑一步：

```
-f concat -safe 0 -i {list.txt} -c copy {output}
```

这一步不使用第 6 节里靠前的 `-i` 位置。`-progress` 仍然放在命令最前面。

### 8.2 需要重新编码

临时段命名为 `0001.mkv`、`0002.mkv`。目标容器是 WebM 时，临时段本身就是 `0001.webm`，避免 VP9 再进一次不必要的封装。

每一段：

```
-i {input} -map 0:v:0 -map 0:a? -vf scale={基准宽}:{基准高} -r {第一段帧率分数} -c:v {编码器} {速度} {质量} -pix_fmt yuv420p -c:a {音频} -ar 48000 -ac 2 {临时段}
```

基准宽高按 LD-06。视频参数与第 7.7 节相同：目标是 MP4 或 MKV 时固定 H.264 族，目标是 WebM 时固定 VP9 族，都使用本任务记下的实现。码率留空或填写的规则也按第 6.1 节。

某一段没有音轨、但其他段有音轨时，不映射源音轨，改加第二条输入：

```
-f lavfi -t {该段时长} -i anullsrc=channel_layout=stereo:sample_rate=48000
```

然后映射这条静音。该段时长缺失时，整次合并失败，说明带上该文件名。

全部临时段成功后，用第 8.1 节的 concat 列表和 `-c copy` 写出最终文件。最终文件只此一个。

任何一段失败、最终拼接失败或用户取消时，删除全部临时段、列表文件和未完成的最终文件。界面进度写「正在合并 {当前段}/{总段数}：{文件名}」。

## 9. 任务编排

文件夹任务的每一项使用独立的取消标记，并链接到整个任务的取消标记。

| 用户动作 | 编排结果 |
| --- | --- |
| 只有一个输入时点取消 | 取消当前标记。该项为已取消。不弹窗 |
| 文件夹任务中选择停掉整个任务 | 取消整个任务。当前项为已取消。还没开始的项为未处理 |
| 文件夹任务中选择只跳过当前文件 | 只取消当前标记。该项为已取消。下一项继续 |
| 关闭询问 | 不取消 |
| 合并过程中点取消 | 取消整个任务。不提供跳过。不留下成片 |
| 关闭主窗口（含运行中） | 只隐藏主界面。任务继续。托盘图标保留 |
| 托盘「退出」（空闲） | 直接退出进程 |
| 托盘「退出」（运行中） | 等同于停掉整个任务。先等清理完成，最多再等 10 秒，然后退出 |

清单顺序与输入顺序相同。每一行是：

```
{文件名}\t{结果}\t{说明}\t{输出路径}
```

结果只用「成功」「失败」「已取消」「未处理」。成功时说明以「已完成」开头，需要时用中文分号接上「已使用 {文件名}」或「已改用 MP4」。失败或取消而文件又删不掉时，说明末尾追加「残留文件：{完整路径}」。复制清单时用 `\r\n` 连接各行。

## 12. 安装脚本

`installer/MediaTool.iss` 由发布脚本调用。版本不写死在脚本里，而由命令传入：

```
ISCC /DMyAppVersion=1.0.0 installer\MediaTool.iss
```

`1.0.0` 必须等于 `CMakeLists.txt` 里 `project(VERSION)` 的版本。发布脚本负责读取并传入。

AppId 使用 `{7C2A6E14-9B35-4F28-A1D6-5E0B8C4F2A91}`。以后升级安装包不得更换这个值。

```iss
#ifndef MyAppVersion
  #error Define MyAppVersion from CMakeLists.txt.
#endif

#define MyAppName "媒体小工具"
#define MyAppDirName "VideoTools"
#define MyAppExe "MediaTool.exe"
#define MyAppId "{{7C2A6E14-9B35-4F28-A1D6-5E0B8C4F2A91}"

[Setup]
AppId={#MyAppId}
AppName={#MyAppName}
AppVersion={#MyAppVersion}
AppPublisher=MediaTool
DefaultDirName={localappdata}\Programs\{#MyAppDirName}
DisableWelcomePage=yes
DisableDirPage=no
DefaultGroupName={#MyAppDirName}
DisableProgramGroupPage=yes
DisableReadyPage=yes
DisableFinishedPage=yes
OutputDir=..\artifacts
OutputBaseFilename=MediaTool-Setup-{#MyAppVersion}
ArchitecturesAllowed=x64compatible
ArchitecturesInstallIn64BitMode=x64compatible
MinVersion=10.0
PrivilegesRequired=lowest
Compression=lzma2
SolidCompression=yes
WizardStyle=modern
UninstallDisplayIcon={app}\{#MyAppExe}

[Files]
Source: "..\publish\*"; DestDir: "{app}"; Flags: ignoreversion recursesubdirs

[Icons]
Name: "{group}\{#MyAppName}"; Filename: "{app}\{#MyAppExe}"
```

安装向导不设置 `LicenseFile`，也不设置 `[Run]` 的安装后启动项，以落实 FR-P-04 和 LD-14。许可证仍随 `publish/licenses/` 复制到安装目录，由关于页打开。安装器只复制 `publish` 目录。卸载由 Inno Setup 删除 `{app}` 和开始菜单项，不包含用户视频目录。

绿色版是 `publish` 目录打成的 `MediaTool-Portable-{版本}.zip`。压缩和解压都不改目录内部布局。

| AT-07 | 合并的第二段 NVENC 失败 | 已写出的临时段被删除，整次改用 `libx264` 重跑；CPU 仍失败时不留下成片 |

发布前仍按需求第 7 节的 AC-01 到 AC-18 在安装版和绿色版上各做一次手工验收。托盘与安装路径简化流程主要在安装版上验收；绿色版同样验收托盘行为。

## 14. 样例准备

`tools/make-samples.ps1` 调用随包或本机用于开发的 FFmpeg，把文件写到 `tests/manual-samples/`。该目录不提交大体积视频。图像字幕样例例外：提交 `tests/fixtures/image-sub.mkv`，其中至少有一条 `hdmv_pgs_subtitle` 或 `dvd_subtitle`。脚本找不到它时打印「缺少图像字幕样例」，并仍然生成其余文件。

脚本生成这些文件：

| 文件 | 用途 | 生成要点 |
| --- | --- | --- |
| `basic.mp4` | 通用输入 | 320×240、2 秒、蓝色、440 Hz、H.264、AAC |
| `two-audio.mp4` | AC-03、保留音轨 | 同一画面加 440 Hz 和 880 Hz 两条 AAC |
| `info.mkv` | AC-02 | 两条音轨、一条 SRT、一条章节、标题为「开场」 |
| `tall.mp4` | AC-10 缩小 | 1920×1080、1 秒 |
| `small.mp4` | AC-10 不放大 | 640×480、1 秒 |
| `merge-a.mp4`、`merge-b.mp4`、`merge-c.mp4` | AC-07 | 三份 1 秒，分辨率分别是 320×240、640×360、160×120 |
| `clip2.mp4`、`clip10.mp4` | AC-08 | 放进同一文件夹 |
| `tone.wav` | AC-12 | 0.4 秒、440 Hz，短于 2 秒视频 |
| `side/clip.mp4` 与 `side/clip.ass` | AC-05 | 只有 ass，没有 srt |
| `side/other.mp4` | AC-05 | 没有配套字幕 |
| `bad.mp4` | AC-07 | 内容是普通文本，扩展名却是 mp4 |

对应的生成命令使用测试信号，不使用外部影片。例如：

```
ffmpeg -y -f lavfi -i color=c=blue:s=320x240:d=2 -f lavfi -i sine=frequency=440:duration=2 -shortest -c:v libx264 -pix_fmt yuv420p -c:a aac basic.mp4
```

```
ffmpeg -y -f lavfi -i color=c=red:s=320x240:d=2 -f lavfi -i sine=frequency=440:duration=2 -f lavfi -i sine=frequency=880:duration=2 -map 0:v -map 1:a -map 2:a -shortest -c:v libx264 -pix_fmt yuv420p -c:a aac two-audio.mp4
```

章节和软字幕用一份临时 SRT，再封装进 MKV。三份合并样例只改变 `color` 滤镜的 `s=` 尺寸。`bad.mp4` 用文本重定向写成，不调用 FFmpeg。

手工验收时，AC-04 的图像字幕部分使用 `tests/fixtures/image-sub.mkv`。其余验收场景使用上表，不依赖用户自己的影片。

## 15. 实现顺序

按这个顺序实现，后面的步骤可以调用前面已经测试过的规则：

1. Domain 的时间、命名、排序、配套文件、容器判断、缩放、信息文本和计划器，并用第 13.1 节锁住。

6. 生成手工样例，按 AC-01 到 AC-18 验收。
